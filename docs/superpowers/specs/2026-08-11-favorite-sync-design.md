# 本地与远端收藏同步设计

日期：2026-08-11  
状态：已确认

## 1. 背景与术语

当前项目只在自部署服务的 SQLite `favorites` 表中保存收藏。JM 账号登录态由后端持有，但本地收藏服务与账号所属服务器的收藏接口尚未关联。

本文中的术语：

- **本地**：当前自部署的 jm-boom 服务及其 SQLite 数据库，不是某个浏览器的本地存储。
- **远端**：当前 JM 账号所属服务器，通过已登录账号的 JWT 访问。
- **同步开启**：用户在设置的账户区域主动开启“收藏同步”，并完成首次差异处理。
- **严格同步**：经 jm-boom 发起的收藏或取消收藏，必须先确认远端达到目标状态，然后才修改本地。

## 2. 目标与非目标

### 2.1 目标

- 收藏同步默认关闭，只在用户主动开启后访问远端收藏。
- 开启时读取两端完整收藏并比较漫画 ID。
- 两端不一致时，在账户设置区域内联提供“合并两端”和“使用远端覆盖本地”，不使用弹窗。
- 完成首次同步后，经自部署服务进行的单项收藏或取消收藏同步到远端。
- 远端操作失败时本地保持不变，设置中展示错误并允许安全重试。
- 同步状态、账号绑定和待重试意图持久化，服务重启后可恢复。
- 多个浏览器或设备同时访问同一自部署服务时，由后端串行化收藏写入。
- 保留现有 `favorites` 数据和关闭同步时的本地收藏行为。

### 2.2 非目标

- 不实时监听 JM 官方客户端或其他客户端直接产生的远端变化。
- 不在同步开启时提供批量清空收藏，因为远端只有逐条 toggle，没有原子批量删除接口。
- 不实现“本地先成功、后台最终同步”的离线队列。
- 不自动决定差异应合并还是覆盖。
- 不自动化操作当前真实账号或 `server/data/app.db` 中的测试收藏。

远端被其他客户端修改后，将在同一账号下次登录自动复检或用户手动点击“重新检查”时发现。

## 3. 方案选择

采用后端统一协调方案：新增 `FavoriteSyncService`，前端只负责控制开关、展示状态和提交用户选择。

未采用的方案：

- 前端编排同步：页面关闭会中断任务，多浏览器之间也容易竞争。
- 本地先写加异步队列：不符合“远端失败时本地不改”的严格同步要求。

## 4. 总体架构

### 4.1 后端组件

新增 `FavoriteSyncService`，负责：

- 读取和持久化同步状态。
- 获取当前已登录 JM 账号身份。
- 分页拉取远端完整收藏。
- 比较本地与远端漫画 ID 集合。
- 执行合并、远端覆盖本地及单项目标状态变更。
- 持久化待重试意图和错误信息。
- 使用进程内异步互斥锁串行化检查、解决差异、重试和收藏写入。
- 监听账号登录、切换和删除事件。

现有 `FavoriteService` 继续负责 SQLite 收藏读写。`FavoriteSyncService` 在它外层协调远端操作，避免把远端协议细节混入存储层。

新增可替换的远端收藏网关：

- 生产实现复用 `JmClient` 和 `EndpointManager`；只读请求使用 `request_with_failover`，toggle 写请求使用不自动重试的单次端点调用。
- 测试实现使用内存假服务，可模拟分页、超时、响应丢失和远端状态变化。

`AppState` 同时保存本地收藏服务和收藏同步服务：

- 收藏列表和漫画收藏状态仍从本地读取。
- 收藏、取消收藏和清空请求必须经过同步服务校验。
- 设置接口直接使用同步服务。

### 4.2 账号生命周期

`AccountService` 增加内部账号会话通知，至少包含登录状态、JM 用户 ID 和用户名，不向前端或日志暴露 JWT、密码。

- 首次开启同步时绑定当前 JM 用户 ID 和用户名。
- 同一账号重新登录且同步已开启时，后台自动复检两端；但如果已有失败的收藏目标或合并任务，则保留该待重试意图，不用普通检查覆盖它。
- 临时登录失败时保留开关和账号绑定，但阻止收藏写入并展示错误，等待重新登录或重试。
- 成功登录为不同 JM 用户 ID、主动更换账号或删除账号时，自动关闭同步并清除同步任务。
- 账号变化不会删除本地收藏。

## 5. 持久化模型

新增迁移 `009_favorite_sync.sql` 和单例表 `favorite_sync_state`。迁移只新增表，不修改或清空现有 `favorites`。

建议字段：

| 字段 | 用途 |
| --- | --- |
| `id` | 固定为 `1` 的单例主键 |
| `enabled` | 同步开关，默认 `0` |
| `account_id` | 绑定的 JM 用户 ID |
| `account_username` | 展示和辅助诊断使用的用户名 |
| `status` | 同步状态 |
| `local_count` / `remote_count` | 最近检查时的两端总数 |
| `local_only_count` / `remote_only_count` | 最近检查时的差异数量 |
| `progress_done` / `progress_total` | 长任务进度 |
| `operation_epoch` | 使已取消或已过期的后台任务失效的递增版本号 |
| `pending_kind` | `check`、`merge`、`remote_overwrite`、`set_favorite` 或空 |
| `pending_comic_id` | 单项失败时的漫画 ID |
| `pending_target` | 单项目标收藏状态 |
| `pending_payload` | 添加收藏所需漫画资料的 JSON |
| `last_error` | 可展示的错误摘要，不保存凭据或完整上游响应 |
| `last_checked_at` | 最近完成远端检查的时间 |
| `last_synced_at` | 最近确认两端一致的时间 |
| `updated_at` | 状态更新时间 |

状态枚举：

- `disabled`：同步关闭。
- `checking`：正在读取并比较两端。
- `needs_resolution`：存在差异，等待用户选择。
- `syncing`：正在合并、覆盖或执行目标状态操作。
- `synced`：最近一次确认两端一致，可执行同步收藏写入。
- `error`：任务失败，等待重试、重新登录或关闭同步。

任何远端副作用发生前先保存待处理意图。这样即使服务在远端成功后、本地提交前退出，重启后仍能通过读取远端实际状态安全恢复。

如果进程启动时发现持久化状态仍为 `checking` 或 `syncing`，将其转换为带“上次操作被中断”说明的 `error`，保留待处理意图并等待用户重试；不会盲目重复 toggle。

## 6. 远端接口与数据归一化

### 6.1 完整收藏列表

使用已认证请求：

`GET /favorite?page=<n>&folder_id=&o=mr`

实现远端 payload 模型，兼容 ID 的 `id`、`aid`、`AID` 别名及字符串/数字混合字段。归一化为与 `FavoriteInput` 相容的漫画摘要。

拉取规则：

- 从第 1 页开始顺序读取，每页按上游约定最多 20 项。
- 根据 `total` 和实际返回长度判断是否继续。
- 按漫画 ID 去重。
- 上游提供非零 `total` 时，最终唯一 ID 数必须与 `total` 相等；不相等则整次快照无效，不能用于覆盖本地。
- 若页码继续增长但没有发现新 ID，立即报错，防止异常响应导致死循环。
- 所有只读请求复用现有端点故障转移逻辑。

远端条目缺失描述、封面或分类时使用空值；分类及子分类标题归一化为本地 `tags`。导入本地时按远端 `mr` 顺序生成稳定的收藏排序值。

### 6.2 单项目标状态

远端写接口 `POST /favorite` 是 toggle，不是幂等的“设置状态”。因此不能直接重复调用。

单项操作先通过 `GET /album?id=<comic_id>` 读取认证响应中的 `is_favorite`：

1. 如果已是目标状态，不调用 toggle。
2. 否则使用 `POST /favorite`，表单字段为 `aid=<comic_id>`。
3. 再次读取 `is_favorite` 验证目标状态。
4. 只有验证成功后才提交本地变化。

toggle 写请求不得使用会自动切换端点并重试的 `request_with_failover`。如果第一个端点已执行成功但响应丢失，自动向第二个端点重试会把收藏状态反向切回。写请求只向当次选定端点发送一次；无论写响应成功还是不确定失败，随后都通过可故障转移的只读请求验证目标状态。验证未达到目标或验证本身失败时进入 `error`，不在同一任务中再次 toggle。

该流程也用于首次合并和失败重试。

## 7. 首次开启与差异处理

### 7.1 开启

开启操作要求当前账号为 `loggedIn`：

1. 保存 `enabled = true` 和账号绑定。
2. 保存待处理类型 `check`，状态改为 `checking`。
3. 后台拉取远端完整收藏，同时读取本地全部收藏。
4. 比较去重后的漫画 ID 集合。
5. 集合相同则清除待处理信息，标记 `synced`。
6. 集合不同则清除 `check` 意图，记录两端总数和差异数量，标记 `needs_resolution`，不修改任何收藏。

若检查失败，状态改为 `error`，保留 `check` 任务供重试。

### 7.2 合并两端

“合并两端”的目标是两端都等于本地与远端的并集：

1. 保存 `merge` 意图并进入 `syncing`。
2. 获取当前两端快照。
3. 对仅本地项目逐项执行“确保远端为已收藏”。
4. 全部远端目标完成后重新拉取远端完整列表。
5. 在一个 SQLite 事务中插入远端独有项目；已有本地项目保留本地资料和原收藏时间。
6. 再次比较本地与远端 ID 集合。
7. 完全一致后清除待处理信息并标记 `synced`。

远端添加过程中失败时，本地保持原状，状态变为 `error`。重试会重新获取远端列表，跳过已经达到目标状态的项目并继续处理剩余项目。

### 7.3 使用远端覆盖本地

“使用远端覆盖本地”不修改远端：

1. 保存 `remote_overwrite` 意图并进入 `syncing`。
2. 重新获取远端完整列表，避免使用过期快照。
3. 在一个 SQLite 事务中删除并重建本地收藏。
4. 事务失败时自动回滚，原本地收藏保持不变。
5. 比较 ID 集合，一致后标记 `synced`。

## 8. 日常收藏与取消收藏

### 8.1 同步关闭

保持现有行为：

- `PUT /api/favorites/:id` 只写本地。
- `DELETE /api/favorites/:id` 只删本地。
- `DELETE /api/favorites` 仍可清空本地。

### 8.2 同步开启且已同步

添加收藏：

1. 保存 `set_favorite`、目标 `true` 和漫画资料。
2. 确保远端目标状态为已收藏并验证。
3. 本地 upsert。
4. 清除任务并恢复 `synced`。

取消收藏：

1. 保存 `set_favorite`、目标 `false` 和漫画 ID。
2. 确保远端目标状态为未收藏并验证。
3. 本地删除。
4. 清除任务并恢复 `synced`。

若远端请求成功但响应丢失，本地尚未变化，状态进入 `error`。重试先读取远端实际状态：若远端已达到目标，只补本地；否则再执行一次经过验证的目标状态流程。

### 8.3 阻塞规则

同步开启时，仅 `synced` 状态允许新的收藏或取消收藏。以下状态由后端返回冲突错误并保持数据不变：

- `checking`
- `needs_resolution`
- `syncing`
- `error`

同步开启时：

- 前端隐藏“清空收藏”。
- 后端仍拒绝 `DELETE /api/favorites`，不能只依赖前端隐藏。

关闭同步会清除差异、错误和待重试任务，但不会主动删除或修改两端收藏。关闭操作递增 `operation_epoch`；后台任务在每次远端副作用、本地事务和状态写入前都校验自己启动时捕获的版本号，发现过期便停止，不能覆盖关闭后的状态。

已经发出的远端 HTTP 请求无法可靠撤回。如果用户恰好在请求进行中关闭同步，该请求可能已经改变远端，但旧任务不会再修改本地；再次开启时必须重新完整检查并让用户处理差异。

## 9. 后端 API

新增接口：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/settings/favorite-sync` | 获取开关、状态、差异、进度、错误和时间 |
| `PUT /api/settings/favorite-sync` | 请求开启或关闭，body 为 `{ "enabled": boolean }` |
| `POST /api/settings/favorite-sync/check` | 手动重新检查 |
| `POST /api/settings/favorite-sync/resolve` | body 为 `{ "strategy": "merge" | "remoteOverwrite" }` |
| `POST /api/settings/favorite-sync/retry` | 按持久化意图安全重试 |

检查、合并和重试可能需要很多上游请求，因此接口只负责验证并启动后台任务，返回当前状态；前端轮询状态。已有任务运行时重复启动返回 `409 Conflict`。

状态响应至少包含：

```json
{
  "enabled": true,
  "status": "needsResolution",
  "accountUsername": "example",
  "localCount": 12,
  "remoteCount": 20,
  "localOnlyCount": 2,
  "remoteOnlyCount": 10,
  "progressDone": 0,
  "progressTotal": 0,
  "pendingKind": null,
  "pendingComicId": null,
  "pendingTarget": null,
  "lastError": null,
  "lastCheckedAt": 1786400000000,
  "lastSyncedAt": null
}
```

返回给前端的错误只包含可操作摘要。JWT、密码、请求签名及完整上游响应不得写入同步表或返回前端。

## 10. 前端交互

账户设置区域新增“收藏同步”区块：

- 从未绑定账号或同步已关闭且当前未登录：开关关闭并禁用，说明需要先登录 JM 账号。
- 已绑定且同步开启、但同一账号暂时未登录：开关保持开启，显示账号错误并允许用户关闭；收藏写入保持禁用。
- 已登录且关闭：允许开启。
- `checking`：显示读取两端收藏的加载状态。
- `needsResolution`：内联显示两端总数、仅本地和仅远端数量，以及两个解决按钮。
- `syncing`：显示已处理/总数进度。
- `synced`：显示已同步、最近成功时间和“重新检查”按钮。
- `error`：显示错误摘要、涉及的漫画 ID（如有）和“重试同步”按钮。

不显示差异弹窗，也不使用全局强制对话框。

前端新增 React Query key 和 API 模块。短任务状态使用普通失效刷新；`checking`、`syncing` 时短间隔轮询，进入稳定状态后停止轮询。

漫画详情的收藏 hook 读取共享同步状态：

- 非 `synced` 的开启状态下禁用收藏按钮。
- 收藏请求失败后立即刷新同步状态。
- 若后端已记录同步错误，toast 引导用户到设置中重试。

收藏页根据同步开关决定是否显示“清空收藏”。后端是最终一致性保护者，前端缓存过期不会绕过限制。

## 11. 并发、故障与恢复

- 一个进程内所有同步任务和收藏写入共用同一异步互斥锁。
- 每个后台任务捕获 `operation_epoch`；关闭同步、账号切换或启动新一代任务时递增版本号，旧任务不能继续产生新的副作用或写回状态。
- 开始远端副作用前持久化意图，完成本地提交后才清除。
- 每次 retry 都重新读取远端，绝不根据“上次请求返回失败”推断远端未变化。
- toggle 写请求不做端点故障转移或传输层自动重试；不确定结果只能通过读取实际状态消歧。
- SQLite 多步替换使用事务。
- 远端分页或验证得到不完整、重复且无进展的数据时进入 `error`，不以部分数据覆盖本地。
- 外部客户端仍可能在检查结束后改变远端；本设计保证经自部署服务发起的操作具有严格目标状态，并在下次登录或手动检查时发现外部漂移。

## 12. 测试策略

自动测试使用内存 SQLite 和模拟远端网关，禁止读取或修改 `server/data/app.db`。

### 12.1 后端测试

- 远端 favorite payload 的混合类型、字段别名和缺失字段反序列化。
- 多页读取、去重、短页结束及无进展保护。
- 两端相同、仅本地、仅远端及双向差异。
- 合并后的并集及本地已有元数据保留。
- 远端覆盖本地及事务回滚。
- 远端已经达到目标状态时不调用 toggle。
- toggle 成功但响应丢失后的幂等重试。
- toggle 写请求发生网络错误时不会自动向第二个端点重复提交。
- 远端成功、本地提交失败后重试只补本地。
- 远端中途失败时本地不变、错误和任务持久化。
- 服务中断状态恢复。
- 同步操作串行化及重复任务冲突。
- 同步中关闭开关后旧任务停止，且不能覆盖 `disabled` 状态或继续写本地。
- 同步未就绪时拒绝写入和清空。
- 同账号重新登录复检，不同账号或账号删除自动关闭。

### 12.2 前端测试与检查

- 将状态到文案、按钮可用性和操作的映射提取为纯函数并测试。
- 验证同步开启时隐藏清空按钮。
- 验证错误状态引导到设置重试。
- 执行格式化检查、lint、TypeScript 构建和现有 Bun 测试。

### 12.3 人工验收

自动测试完成后保留当前真实数据。由用户：

1. 登录当前测试账号。
2. 确认开关默认关闭，且未发生远端请求或数据变化。
3. 开启同步，确认检测到预先新增的本地收藏差异。
4. 选择“合并两端”，确认该收藏出现在远端且两端数量一致。
5. 在 jm-boom 中收藏、取消收藏，确认远端同步变化。
6. 模拟远端不可用，确认本地不变、设置显示失败且恢复后可重试。
7. 更换账号，确认同步自动关闭且本地收藏保留。

## 13. 验收标准

- 新安装或迁移后收藏同步默认关闭。
- 关闭状态不访问远端收藏，不改变现有本地行为。
- 开启后完整检查两端，差异只在设置区域内联展示。
- 合并产生两端并集；远端覆盖本地不会写远端。
- 进入 `synced` 前必须再次确认 ID 集合一致。
- 同步模式下单项写入先验证远端目标状态，远端失败时本地不变。
- 错误和待重试意图在服务重启后仍存在，重试不会反向 toggle。
- 账号切换或删除自动关闭同步，不删除本地收藏。
- 同步开启时前端隐藏且后端拒绝批量清空。
- 自动测试不接触真实账号和当前本地数据库。
