# 漫画详情页操作区与主导航布局设计

日期：2026-08-13
状态：待实现前终审

## 1. 目标

漫画详情页不再使用固定在屏幕底部的“阅读、收藏、下载”操作胶囊。三个漫画操作回到页面内容中，同时详情页底部恢复主界面同款导航胶囊，方便跳转书架、探索、收藏、下载和设置。

## 2. 页面内操作区

- 阅读、收藏、下载按钮紧跟漫画简介，位于标签等元数据之前。
- 移动端采用用户确认的 B 方案：三个按钮在同一行，均显示图标和完整文案；阅读按钮显示现有动态文案，例如“开始阅读”“从第 X 话继续”或单章漫画的“继续阅读”。
- 桌面端保持现有自然宽度和按钮视觉。
- 所有屏幕尺寸共用同一个操作组件和同一套事件、忙碌状态，不再维护移动端固定操作组件。
- 收藏状态、收藏同步、下载抽屉、阅读目标及预加载行为均保持不变。

## 3. 底部主导航

- `_app` 在漫画详情路由也渲染现有 `FloatingNav`，直接复用主界面的 5 个入口和样式，不复制导航实现。
- 漫画详情路由不属于任一主栏目，因此 5 个入口均不高亮。
- 详情页保留足够的底部内边距，避免相关漫画等末尾内容被固定导航遮挡。
- Reader 路由位于 `_app` 之外，不显示该主导航，行为不变。

## 4. 代码边界

- 将 `ComicHero` 中移动端、桌面端两套操作渲染合并为一个响应式页面内操作组件。
- 删除不再使用的 `ComicDetailFloatingActions` 组件文件及引用。
- `_app` 去掉漫画详情页隐藏主导航的条件；现有路径匹配逻辑会令详情页 `activeId` 为空。
- 不修改漫画详情数据、收藏和下载 API、Reader 导航、章节列表或路由结构。

## 5. 测试与验收

- 为主导航显示/激活判定增加纯函数测试：详情页显示且无激活项，Reader 不经过 `_app`，已有主栏目仍正确高亮。
- 前端全量测试、Lint、生产构建及触及文件格式检查通过。
- 移动端详情页页面内可见三个完整文案按钮，滚动时随内容离开视口；底部固定区域仅显示主导航。
- 桌面端详情页操作按钮与现有行为一致，并显示主导航。

## 6. 提交边界

设计文档单独提交。实现形成一个独立提交，不推送远端，除非用户另行要求。
