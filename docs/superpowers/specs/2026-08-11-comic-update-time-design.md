# 漫画更新日期展示收口设计

日期：2026-08-11
状态：已确认（修订版，待文档复核）

## 1. 背景与上游能力

收藏页面已经支持按账号服务器的 `o=mr`（收藏时间最新）和 `o=mp`（更新时间最新）浏览。此前方案准备为收藏卡片和每个章节补齐具体更新时间，并在详情页显示上架日期与更新日期。

实际请求当前上游移动 API 后确认：

- 漫画详情 `album` 响应只有漫画级 `addtime`，没有 `datePublished`。
- 详情中的 `series` 章节条目只有章节 ID、标题和排序，不含章节时间。
- 网页版的 `datePublished` 属于网页结构化数据，不是当前移动 API 字段。
- 单章接口虽有 `addtime`，但逐章请求会增加等待时间，且用户已经取消章节时间展示。

因此本轮收口为：只在漫画详情页显示漫画级更新日期，不抓取网页版，不显示上架日期、收藏卡片时间或章节时间。

## 2. 目标

- 漫画详情页在标题和作者下方显示 `更新日期 YYYY-MM-DD HH:mm`。
- 更新日期直接使用漫画详情上游响应中的有效 `addtime`。
- 收藏页继续支持 `mr/mp` 排序，但不显示具体更新时间，也不为时间补齐请求漫画详情。
- 章节卡片继续只显示原有 `JM 章节ID` 胶囊，不显示日期胶囊。
- 删除仅服务于收藏和章节时间补齐的缓存、模型字段与数据传递，避免遗留无效复杂度。
- 时间缺失时仅隐藏详情页更新日期，不影响详情页其他内容。

## 3. 非目标

- 不显示或估算上架日期。
- 不抓取网页版 `datePublished`，不新增 HTML 或 JSON-LD 解析。
- 不显示收藏卡片更新时间。
- 不获取或缓存每章更新时间。
- 不修改收藏 `mr/mp` 排序、收藏同步、浏览量、喜欢数、评论数或章节数。
- 不实现章节标题改写、已读章节置灰和继续阅读文案等其他后续需求。

## 4. 后端设计

### 4.1 漫画详情时间

远端漫画详情负载只解析顶层 `addtime`。该字段接受正数 Unix 秒时间戳，并兼容 JSON 数字与数字字符串；空值、零、负数、非数字和越界值均视为缺失。

领域模型只增加 `ComicDetail.updated_at: Option<i64>`，漫画详情 API 只增加 `updatedAt: number | null`。不增加 `publishedAt`，也不在章节对象中增加 `updatedAt`。

详情请求仍只执行原有的一次 `album` 请求，不增加其他网络访问。`addtime` 缺失时返回 `updatedAt: null`。

### 4.2 收藏列表

收藏列表继续通过以下接口获取远端顺序：

`GET /api/favorites?page=<positive-integer>&order=mr|mp`

无论选择 `mr` 还是 `mp`，后端都只执行获取该页收藏数据所需的现有请求，不再逐项请求漫画详情。收藏响应不增加 `updatedAt`，也不解析或传递仅用于时间缓存版本的 `latest_ep_aid`。

### 4.3 删除的后端设计

删除此前为时间补齐新增的以下内容：

- 24 小时章节时间缓存及其服务状态。
- 通过最新章节 ID 查询或预热缓存的逻辑。
- `mp` 当前页最多 4 并发的漫画详情补齐任务。
- 漫画章节时间字段及其推导规则。
- 漫画上架日期字段及“章节最大时间回退”规则。

收藏同步和远端排序实现不依赖这些时间字段，保持原有行为。

## 5. 前端设计

保留 Unix 秒时间格式化工具，按浏览器本地时区输出 `YYYY-MM-DD HH:mm`。

漫画详情头部在标题和作者下方只显示：

`更新日期 YYYY-MM-DD HH:mm`

时间无效或缺失时不渲染该行。现有浏览量、喜欢数、评论数和章节数原样保留。

收藏卡片恢复原有标题与作者布局，不接收时间展示开关，不渲染日期。章节卡片右侧恢复为单个 `JM 章节ID` 胶囊，不再使用上下两个胶囊的纵向布局。

## 6. 加载与降级

- 收藏页不等待逐本漫画详情，加载时间只取决于原有收藏页与同步一致性流程。
- 详情页不增加第二个请求，更新日期随漫画详情一起返回。
- 更新日期缺失不视为请求错误，不显示占位符，也不影响详情、章节和统计内容。
- 不缓存时间数据；重新打开详情页时沿用现有详情查询缓存策略。

## 7. 测试方案

### 7.1 后端

- 顶层 `addtime` 接受正数数字与数字字符串，并拒绝无效值。
- 漫画详情 API 正确输出 `updatedAt`，缺失时输出 `null`。
- 漫画详情与章节响应不包含 `publishedAt` 或章节 `updatedAt`。
- `mr/mp` 收藏列表都不触发逐项漫画详情请求，且排序与总数保持不变。
- 现有收藏同步、排序和详情测试继续通过。

### 7.2 前端

- 时间格式化精确到分钟并安全处理无效值。
- 详情头部只显示更新日期，不显示上架日期。
- 收藏卡片和章节卡片均不显示时间。
- 现有统计、收藏排序及其他漫画网格调用方保持不变。

### 7.3 全量验证

运行后端测试、Rust 格式与 Clippy、前端测试、Lint 和生产构建。使用已登录测试账号验证：

- 收藏页 `mr/mp` 均只返回对应远端顺序，不再等待逐本详情补齐。
- 漫画详情只显示可用的更新日期。
- 章节右侧只保留原有 ID 胶囊。

## 8. 验收标准

- 收藏页保留按收藏时间和更新时间排序，但不显示卡片时间且不执行时间补齐请求。
- 漫画详情页不显示上架日期，只显示有效的漫画更新日期。
- 所有章节均不显示更新时间或日期胶囊。
- 不存在章节时间缓存、最新章节 ID 时间链路或逐项详情并发补齐逻辑。
- 单个更新日期缺失不会导致详情页失败。
- 现有收藏同步、统计信息和其他已实现功能不受影响。
