# 漫画更新时间展示设计

日期：2026-08-11
状态：已确认

## 1. 背景

收藏页面已经支持按账号服务器的 `o=mr`（收藏时间最新）和 `o=mp`（更新时间最新）顺序浏览，但收藏列表响应只提供顺序，不提供可展示的具体更新时间。漫画详情上游响应包含漫画 `addtime` 以及每章 `series[].addtime`，当前项目尚未解析和暴露这些字段。

漫画详情页面已经显示浏览量、喜欢数、评论数和章节数。本功能不重复或修改这些统计，只补充日期信息，并让收藏页和详情页共用同一套漫画详情时间解析。

## 2. 目标与非目标

### 2.1 目标

- 收藏页选择“更新时间最新”时，在当前页每张漫画卡片的文字区域右下角显示更新时间。
- 收藏页只补齐当前页数据，不预取后续页。
- 漫画详情页在标题和作者下方显示上架日期与更新日期。
- 每个章节卡片右侧在现有 `JM 章节ID` 胶囊下方显示章节更新时间胶囊。
- 收藏页和漫画详情页使用相同的上游字段解析、时间推导和格式化规则。
- 使用最新章节 ID 驱动的 24 小时章节时间缓存，减少重复详情请求，同时保证新增章节立即绕过旧缓存。
- 单本漫画或单个时间字段失败时安全降级，不阻断其余内容。

### 2.2 非目标

- 不修改现有浏览量、喜欢数、评论数和章节数的布局或文案。
- 不实现原后续需求中的章节标题改写、章节正逆序按钮调整、已读章节置灰和继续阅读文案修改。
- 不缓存完整漫画详情。
- 不预取未访问的收藏页。
- 不新增定时后台刷新或轮询。
- 不持久化章节时间缓存；服务重启后允许重新获取。

## 3. 时间语义

上游时间只接受正数 Unix 秒时间戳，兼容 JSON 数字和数字字符串。空值、零、负数、非数字及超出可表示范围的值均归一化为缺失。

| 展示字段 | 数据来源 | 回退规则 |
| --- | --- | --- |
| 上架日期 | 漫画详情顶层 `addtime` | 无有效值则隐藏 |
| 章节更新时间 | 对应 `series[].addtime` | 无有效值则隐藏该日期胶囊 |
| 漫画更新日期 | 所有有效章节更新时间的最大值 | 没有有效章节时间时回退到上架日期 |

后端 API 统一返回可选 Unix 秒时间戳。前端按浏览器本地时区格式化为 `YYYY-MM-DD HH:mm`，不在后端提前拼接日期字符串。

## 4. 后端设计

### 4.1 共享详情模型

远端详情负载增加可选的漫画和章节 `addtime` 解析。领域模型扩展为：

- `ComicDetail.published_at`：上架时间。
- `ComicDetail.updated_at`：按第 3 节规则推导的漫画更新时间。
- `ComicChapter.updated_at`：章节更新时间。

`ComicService::get_comic_detail` 仍执行一次现有 `album` 请求，并在一次转换中生成全部字段。详情页不为日期增加第二次网络请求，也不为每一章单独发请求。

漫画详情 API 响应增加：

- 顶层 `publishedAt: number | null`。
- 顶层 `updatedAt: number | null`。
- 每个章节的 `updatedAt: number | null`。

这些字段为向后兼容的新增字段，现有调用方可以忽略。

### 4.2 最新章节标识

远端收藏条目解析现有的 `latest_ep_aid` 字段，并归一化为可选最新章节 ID。该 ID 只作为列表补齐和缓存版本使用，不写入本地 `favorites` 表，也不暴露给前端。

同步完成后的远端排序读取继续用远端漫画 ID 关联本地收藏元数据，同时将该页各条目的最新章节 ID 保留到 API 组装阶段。收藏集合校验、账号校验和远端顺序保持规则不变。

### 4.3 章节时间缓存

后端增加进程内章节时间缓存，键为章节 ID，值包括有效章节时间与写入时刻：

- 有效期为 24 小时，过期条目在读取时视为未命中并惰性替换。
- 只缓存成功解析出的有效时间；请求失败或缺失时间不做负缓存，后续请求仍可重试。
- 任意漫画详情请求成功后，将响应内全部有效章节时间写入缓存，使详情页和收藏页可以相互预热。
- 服务重启后缓存清空，不引入数据库迁移。

收藏页每次仍实时请求远端 `mp` 当前页。对每个条目：

1. 使用远端最新章节 ID 查询章节时间缓存。
2. 命中未过期缓存时直接作为漫画更新时间。
3. 未命中时请求该漫画详情，使用推导出的漫画更新时间，并缓存详情内有效章节时间。
4. 如果远端最新章节 ID 与详情章节暂时不一致，但详情已得到有效漫画更新时间，则以该最新章节 ID 写入同样的 24 小时缓存值，避免同一远端版本反复请求。
5. 没有最新章节 ID 时直接请求详情；这类条目不使用章节 ID 缓存捷径。

漫画新增章节后，远端当前页返回的最新章节 ID 会变化，因此旧章节 ID 缓存不会命中，新章节时间会立即请求。若远端修正同一章节 ID 的原时间，最迟在 24 小时缓存到期后刷新。

### 4.4 收藏当前页补齐

收藏列表 API 继续使用：

`GET /api/favorites?page=<positive-integer>&order=mr|mp`

收藏响应条目增加 `updatedAt: number | null`：

- 仅 `order=mp` 执行更新时间补齐。
- 只处理远端当前页返回的最多 20 条记录，不请求其他页。
- 缓存未命中的详情请求最多同时执行 4 个，并在完成后恢复原有远端 `mp` 顺序。
- `order=mr` 不读取章节时间缓存、不请求漫画详情，`updatedAt` 返回 `null`。
- 收藏新增接口返回的单条记录同样以 `updatedAt: null` 保持统一合约。

某一详情请求失败时记录后端警告并将对应 `updatedAt` 留空；基础收藏列表仍成功返回。远端收藏列表本身失败、同步状态冲突或集合不一致时，继续使用已有整页错误行为。

## 5. 前端设计

### 5.1 共享格式化

增加一个只负责 Unix 秒时间戳校验和本地格式化的工具，输出固定宽度的 `YYYY-MM-DD HH:mm`。输入缺失、非有限数字或不能转换为有效日期时返回空结果，由调用方隐藏日期。

### 5.2 收藏卡片

收藏 API 类型增加 `updatedAt: number | null`。收藏页把当前排序状态显式传给漫画网格：

- `order=mp` 且时间有效时，在作者信息下方增加一行浅色小字，位于卡片文字区域最下方并右对齐。
- `order=mr` 时不渲染该行，即使数据对象意外带有时间也不展示。
- 时间不可用时保留卡片、标题和作者，只省略日期行。

通用漫画卡片和网格只增加可选的更新时间展示能力；首页、搜索页及其他现有调用方默认行为不变。

### 5.3 漫画详情头部

详情页领域类型和 API 映射增加 `publishedAt`、`updatedAt`。在标题和作者下方增加浅色日期区域：

- `上架日期 YYYY-MM-DD HH:mm`
- `更新日期 YYYY-MM-DD HH:mm`

宽屏优先同一行展示，窄屏允许自然换行。任一字段缺失时只隐藏对应项；两项都缺失时不渲染整个日期区域。现有统计栏原样保留。

### 5.4 章节卡片

章节类型增加 `updatedAt`。章节卡片右侧由单个徽标改为右对齐的纵向区域：

1. 上方保留现有 `JM 章节ID` 胶囊。
2. 下方新增 `YYYY-MM-DD HH:mm` 日期胶囊。

两个胶囊上下居中并保持右对齐，左侧章节标题区域继续允许截断。章节时间无效时只显示原有 ID 胶囊。单行本没有上游章节时间时不新增日期胶囊。

## 6. 加载、并发与降级

- 收藏页等待当前页基础数据和必要的时间补齐完成后一次性渲染，不让卡片时间逐条跳出。
- 章节时间缓存命中不会触发详情请求；未命中的请求使用最多 4 个并发，避免一次打开页面同时向远端发送 20 个请求。
- 补齐期间切换页码或排序时，前端沿用查询键隔离和请求结果生命周期，不将上一页时间写入当前页。
- 单条补齐失败不将整个收藏查询标记为失败，也不缓存失败结果。
- 详情接口请求失败继续使用现有详情页错误和重试界面；仅某个时间缺失不视为详情请求失败。
- 24 小时缓存只覆盖章节时间，不改变远端收藏顺序、同步一致性检查或漫画详情的现有前端缓存策略。

## 7. 测试方案

### 7.1 后端

- 时间反序列化接受数字和数字字符串，拒绝空值、零、负数、非数字及越界值。
- 漫画更新时间取有效章节时间最大值，无有效章节时间时回退到上架时间。
- 漫画详情 API 序列化顶层和章节时间字段，缺失值为 `null`。
- 收藏负载正确解析 `latest_ep_aid`，同时不把它持久化到收藏表。
- 章节时间缓存覆盖命中、24 小时过期、无效值不缓存及服务内共享预热。
- 最新章节 ID 不变且缓存命中时不请求详情；ID 变化或缓存过期时请求详情。
- `mp` 只补齐当前页、最多 4 个并发并保持原顺序；`mr` 不请求详情。
- 单条详情失败只让对应时间为空；基础列表、其他时间和总数仍返回。
- 现有收藏同步、排序、漫画详情和 API 合约测试继续通过。

### 7.2 前端

- 时间格式化按本地时间输出到分钟，并安全处理缺失和无效时间。
- 收藏卡片仅在 `mp` 下显示右对齐更新时间，`mr` 和缺失时间均不显示。
- 详情头部显示上架与更新日期，并覆盖单项缺失和全部缺失。
- 章节右侧以 ID 胶囊在上、日期胶囊在下展示；缺失时间时保留 ID 胶囊。
- 现有浏览、喜欢、评论、章节统计以及其他漫画网格调用方保持不变。

### 7.3 全量验证

运行后端单元与集成测试、Rust 格式与 Clippy、前端测试、前端 Lint 和生产构建。使用已登录测试账号验证：

- `mp` 第 1 页只补齐该页漫画，顺序与远端一致。
- 首次访问产生详情请求，再次访问命中章节时间缓存。
- 远端出现新章节后，最新章节 ID 变化并立即取得新时间。
- 详情页日期和章节胶囊在桌面与窄屏布局中均不遮挡主要内容。

## 8. 验收标准

- 收藏页选择“更新时间最新”后，每个有有效数据的当前页漫画卡片在文字区域右下角显示精确到分钟的更新时间。
- 收藏页选择“收藏时间最新”时不显示更新时间，也不产生详情补齐请求。
- 第 1 页不会预取第 2 页；缓存未命中时详情请求并发不超过 4。
- 缓存以最新章节 ID 区分版本，有效期 24 小时；新增章节不会被旧缓存遮住。
- 漫画详情页显示可用的上架日期和更新日期，每章右侧在原 ID 胶囊下显示可用的更新时间胶囊。
- 现有浏览和喜欢统计不增加、不删除、不改文案。
- 单个时间缺失或单本详情补齐失败不会导致整页失败。
- 原后续需求第 3–6 项没有被本轮改动。
