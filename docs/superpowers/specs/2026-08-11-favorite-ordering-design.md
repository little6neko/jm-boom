# 收藏页面排序设计

日期：2026-08-11
状态：待书面确认

## 1. 背景

收藏页面当前只按自部署服务 SQLite `favorites.favorited_at` 倒序展示。该字段能表达本地收藏时间，但从远端首次同步进来的条目只能依据远端 `o=mr` 返回顺序生成近似时间，不能视为账号服务器保存的真实收藏时间。

JM 网页的 `/favorite/albums` 列表以及项目现有的远端收藏 API 请求支持同一组 `o` 排序参数：

- `o=mr`：最近收藏在前。
- `o=mp`：最近更新在前。

两种请求返回相同的收藏集合，但顺序不同。远端条目没有提供可供本地持久化的收藏时间或更新时间，因此本功能直接使用远端列表顺序，不伪造时间字段。

本文中的“同步完成”指收藏同步已开启、当前账号与同步绑定账号一致，且后端持久化状态为 `synced`。

## 2. 目标与非目标

### 2.1 目标

- 收藏页面支持“收藏时间最新”和“更新时间最新”两种倒序排列。
- 同步完成时，两种排列均在列表请求时使用账号服务器的 `mr` 或 `mp` 顺序。
- 未同步时继续允许按本地收藏时间浏览，但不提供没有可靠数据来源的更新时间排序。
- 排序状态写入页面 URL，刷新、前进和后退后保持一致。
- 排序切换、收藏增删和同步完成后不会继续展示另一排序方式的旧缓存。
- 列表请求检测到远端与本地收藏集合不一致时，不返回看似正确但实际缺项的排序结果。

### 2.2 非目标

- 不提供升序排列。
- 不在本地新增或伪造漫画更新时间、远端收藏时间字段。
- 不修改现有收藏同步开关、首次差异解决和失败重试规则。
- 不自动合并当前节点与其他 JM 节点的缓存；排序遵循现有端点选择与只读故障转移策略。
- 不在每次打开页面时拉取远端完整收藏快照，只读取当前页并做必要的一致性校验。

## 3. 排序语义

新增受限排序值：

| 值 | 页面文案 | 数据来源 |
| --- | --- | --- |
| `mr` | 收藏时间最新 | 同步完成时使用远端 `o=mr`；否则使用本地 `favorited_at DESC, comic_id DESC` |
| `mp` | 更新时间最新 | 仅同步完成时使用远端 `o=mp` |

默认值为 `mr`。省略或无法识别的页面 URL 排序值回退并规范为 `mr`；后端 API 收到 `mr`、`mp` 以外的值则返回参数错误，不自行猜测。

同步完成时，即使选择 `mr`，也不再依据本地 `favorited_at` 排序，而是使用请求时取得的远端 `mr` 顺序。这样能避免首次导入产生的近似时间、在其他客户端收藏产生的时间以及本地历史数据漂移影响排序。

以下任一情况均视为“未同步”：

- 未登录账号。
- 收藏同步开关关闭。
- 同步状态为 `checking`、`needs_resolution`、`syncing`、`error` 或 `disabled`。
- 当前登录账号与同步绑定账号不一致。

未同步时：

- `mr` 使用现有本地分页和排序，收藏页面仍可正常使用。
- `mp` 在界面中不可选；直接请求后端 `order=mp` 返回 `409 Conflict`。
- 如果用户通过旧书签或手工 URL 进入 `?order=mp`，前端使用替换导航切回 `?order=mr`，页码重置为 1。

## 4. 后端设计

### 4.1 API 合约

收藏列表接口扩展为：

`GET /api/favorites?page=<positive-integer>&order=mr|mp`

- `order` 可省略，省略时默认为 `mr`，兼容现有调用方。
- 响应结构和现有分页大小保持不变。
- 无效 `order` 返回 `400 Bad Request`。
- 未同步时请求 `mp` 返回 `409 Conflict`，错误信息说明需要先登录并完成收藏同步。
- 预期使用远端排序时，远端请求失败直接返回现有上游错误，不静默退回本地排序。
- 发现远端和本地收藏不一致时返回 `409 Conflict`，提示用户前往设置重新检查同步。

为避免前端依赖中文错误文案，收藏列表的冲突响应在现有 `{ error, retryable }` 结构上增加稳定的可选 `code`：

- `favorite_order_unavailable`：当前状态不能使用 `mp`。
- `favorite_sync_mismatch`：远端总数不同或远端页面中存在本地缺失 ID。
- `favorite_order_stale`：远端请求期间账号或同步状态发生变化，本次结果已过期。

`code` 是共享错误响应的向后兼容可选字段；其他现有错误不必提供。前端按 `code` 决定回退、引导重新检查或重新查询，中文 `error` 只用于展示。

### 4.2 远端排序参数

新增内部枚举 `FavoriteOrder`，仅允许 `Mr` 和 `Mp`，分别序列化为 `mr`、`mp`。枚举从 API 层一直传递到远端收藏网关，避免在中间层使用任意字符串。

现有同步快照、首次差异检查和覆盖流程继续显式使用 `Mr`，保持原有远端收藏导入顺序。新增的收藏页面只读能力按用户选择传递 `Mr` 或 `Mp`，不改变远端收藏状态。

### 4.3 同步服务读取流程

`FavoriteSyncService` 提供按远端顺序读取单页收藏的只读方法：

1. 在同步互斥与状态存储的现有约束下，确认账号已登录、账号绑定一致、同步已开启且状态为 `synced`。
2. 捕获当前账号 ID、会话标识和 `operation_epoch`。
3. 请求账号服务器当前页，并传入所选 `mr` 或 `mp`。
4. 请求完成后重新读取状态，确认账号、会话、`synced` 状态及 `operation_epoch` 均未变化。
5. 比较远端响应的 `total` 与本地收藏总数；不相等则返回冲突。
6. 按当前页的远端漫画 ID 批量读取本地记录。任一远端 ID 在本地不存在则返回冲突。
7. 按远端 ID 原始顺序重组本地记录并返回，不能依赖 SQL 的 `IN` 查询顺序。

步骤 1 与步骤 4 的双重校验避免远端请求进行期间发生关闭同步、账号切换或新同步任务后，旧响应仍被页面采用。该只读流程不更新同步状态、不写入 `favorites`，也不触发远端 toggle。

总数相同但集合被远端以“一增一减”方式改变时，当前页包含本地缺失 ID 即会返回冲突；若变化尚未出现在已访问页，后续访问对应页面或手动重新检查时发现。为避免每次翻页都拉取完整集合，本功能不将完整差异检查合并进列表请求。

### 4.4 本地仓库读取

收藏仓库新增：

- 读取本地收藏总数。
- 按一组漫画 ID 批量读取收藏。

批量读取使用参数绑定，空 ID 列表直接返回空结果。读取后以 ID 建立映射，再按照远端响应顺序组装，避免逐条查询造成 N+1 请求。现有未同步 `mr` 查询继续使用：

`ORDER BY favorited_at DESC, comic_id DESC`

本功能不需要数据库迁移。

## 5. 前端交互

### 5.1 排序选择器

收藏页标题区域复用现有筛选选择器，提供：

- `收藏时间最新`
- `更新时间最新`

默认选择 `收藏时间最新`。选择器变化时写入 `?order=mr` 或 `?order=mp`，并将当前页重置为第 1 页。浏览器刷新、前进和后退均由 URL 恢复选择。

未同步时“更新时间最新”显示为不可用；若现有选择器不支持禁用单项，则扩展其选项模型加入 `disabled`，而不是隐藏整个排序控件。不可用提示说明“登录并完成收藏同步后可用”。

### 5.2 查询与缓存

收藏列表查询键包含 `page` 和 `order`，等价于 `favorites(page, order)`。所有收藏列表键仍共享稳定的 `favorites` 前缀，以便一次失效两种排序缓存。

- 收藏列表查询的 `staleTime` 设为 0，使重新进入页面、切换排序、翻页以及切回已访问排序时都重新读取当前顺序；本功能不增加定时轮询。
- 本地回退查询可以沿用相同缓存策略，减少两条分支的行为差异。
- 收藏或取消收藏成功后，使整个 `favorites` 前缀失效。
- 收藏同步检查、合并、远端覆盖或失败重试成功进入 `synced` 后，使整个 `favorites` 前缀失效。
- 排序切换使用独立查询键，不在加载新顺序时把上一种排序标记为当前结果。

### 5.3 加载与错误

- 加载时沿用收藏页面现有加载态。
- 普通远端读取失败沿用现有错误展示和重试入口。
- 收到 `favorite_sync_mismatch` 时，明确提示“本地与远端收藏已不一致，请在设置中重新检查同步”，并提供进入设置的入口。
- 收到 `favorite_order_stale` 时自动重新查询一次；若状态已变成未同步，则按未同步规则回退到 `mr`。
- 不一致或网络失败时不静默展示本地 `mr` 结果，因为这会让用户误以为当前选择的远端顺序有效。
- 页面因未同步而从 `mp` 回退到 `mr` 不作为错误，只更新 URL 和选择器。

## 6. 并发与兼容性

- 旧前端未传 `order` 时仍得到 `mr`，API 保持向后兼容。
- 收藏列表只读请求不持有跨网络调用的全局写锁；依靠调用前后状态与版本校验拒绝过期结果，避免阻塞收藏同步任务。
- 收藏增删或同步任务在远端列表请求期间改变 `operation_epoch` 或同步状态时，该列表请求返回冲突，前端重新查询。
- 远端只读请求继续使用现有故障转移。若某个可用 JM 节点自身缓存较旧，本功能不会跨节点汇总或猜测哪个顺序更新；用户可沿用现有节点切换及重新检查机制。

## 7. 测试方案

### 7.1 后端

- `FavoriteOrder` 只接受 `mr`、`mp`，默认值为 `mr`，其他值返回 400。
- 假远端记录收到的排序参数，验证 API 将 `mr` 和 `mp` 原样传递。
- 假远端对两种排序返回不同 ID 顺序，验证响应严格保持对应远端顺序。
- 验证批量本地查询不会改变远端 ID 顺序，并覆盖空页。
- 未同步、未登录、账号不一致及非 `synced` 状态下：`mr` 使用本地排序，`mp` 返回 409。
- 远端 `total` 与本地数量不同或当前页存在本地缺失 ID 时返回带 `favorite_sync_mismatch` 代码的 409。
- 远端请求期间账号、会话、同步状态或 `operation_epoch` 变化时拒绝旧结果。
- 三种收藏排序冲突响应包含稳定的机器可读 `code`，现有其他错误 JSON 合约保持兼容。
- 远端失败时不退回本地结果。
- 现有同步快照继续固定使用 `mr`，收藏同步、增删和重试测试全部通过。

### 7.2 前端

- 缺少或无效 URL 参数时规范为 `mr`。
- 切换 `mr`、`mp` 会更新 URL、查询键并重置到第 1 页。
- 同步完成时两项均可选；未同步时 `mp` 禁用。
- 直接进入不可用的 `?order=mp` 时替换为 `?order=mr`。
- `favorite_order_unavailable`、`favorite_sync_mismatch` 和 `favorite_order_stale` 分别触发安全回退、重新检查指引和一次重新查询；普通远端错误保留手动重试能力。
- 收藏增删和同步完成会同时失效 `mr`、`mp` 缓存。
- 现有收藏页面空态、分页、删除及清空行为保持通过。

### 7.3 全量验证

运行后端单元与集成测试、前端测试、Rust 格式与 Clippy、前端 Lint 和生产构建。

## 8. 验收标准

- 收藏页面可以在“收藏时间最新”和“更新时间最新”之间切换，显示顺序分别与当前账号服务器 `o=mr`、`o=mp` 的当前页顺序一致。
- 同步完成时 `mr` 不使用本地近似时间；未同步时 `mr` 仍能正常显示本地收藏。
- 未登录或未完成同步时无法选择 `mp`，旧 URL 能安全回退到 `mr`。
- 切换排序必定回到第 1 页，刷新与浏览器导航保持所选顺序。
- 远端和本地数量不同或页面包含本地缺失收藏时，页面提示重新检查同步，不显示错误顺序。
- 功能不新增收藏时间或更新时间数据库字段，不改动远端收藏，也不破坏现有收藏同步流程。
