# 收藏合并阶段文案设计

日期：2026-08-11

## 背景

设置页现有收藏同步卡片会在进度条上方显示一行状态文案。用户点击“合并两端”后，后台实际依次执行三段工作，进度条也会依次重新计数，但当前三段都显示“正在同步收藏”，无法判断正在进行哪一步。

“重新检查”时现有文案“正在读取并比较两端收藏”表达准确，必须保持不变。

## 目标

仅在“合并两端”执行期间，让现有进度条上方的同一行文案按实际阶段依次显示：

1. `正在拉取远端收藏`
2. `正在上传本地收藏`
3. `正在检查同步结果`

每次进入新阶段时，现有进度条按该阶段的工作量从头计数。顶部“正在同步”徽标、卡片布局和其他同步规则均不改变。

## 非目标

- 不显示漫画封面、标题、ID、队列或操作日志。
- 不新增进度条、阶段列表、弹窗或展开区域。
- 不合并三次进度，也不改变收藏合并顺序。
- 不修改首次开启或点击“重新检查”时的“正在读取并比较两端收藏”文案。
- 不改变“远端覆盖本地”、单项收藏、取消收藏、失败重试和账号切换行为。

## 状态与接口

后端同步状态新增一个可空的结构化阶段字段 `progressPhase`，取值为：

- `fetchingRemote`：正在取得用于合并的第一份远端收藏快照。
- `uploadingLocal`：正在将仅本地存在的收藏逐项同步到远端。
- `verifying`：正在重新拉取远端快照并核对合并结果。

该字段只在 `status=syncing` 且当前任务为 `merge` 时使用，其他状态为 `null`。后端在每一阶段开始实际网络或本地操作前，原子地更新阶段并重置该阶段的 `progressDone` 与 `progressTotal`，确保前端轮询不会把上一阶段的数字配到下一阶段文案。

阶段随同步状态一起持久化，使浏览器刷新后仍能展示准确文案。合并成功、失败、取消、关闭同步或账户变化时清空阶段。合并失败后点击重试，将从现有安全重试流程重新执行，并再次依次发布三个阶段。

## 后端流程

`run_merge` 保持现有业务顺序，仅增加阶段状态更新：

1. 设置 `fetchingRemote`，进度归零，拉取完整远端收藏。
2. 计算仅本地收藏，设置 `uploadingLocal` 及总数，逐项上传并推进进度。
3. 设置 `verifying`，进度归零，重新拉取完整远端收藏，将仅远端收藏补入本地并比较两端 ID 集合。
4. 验证通过后进入 `synced` 并清空 `progressPhase`。

阶段状态不参与远端写入决策，也不改变已有的幂等检查、单端请求、失败保留和重试语义。

## 前端展示

设置页继续使用当前红框位置的一行文字。前端根据 `progressPhase` 映射上述三条固定中文文案；若同步状态不是合并阶段或字段未知，则保留现有安全回退文案“正在同步收藏”。

`status=checking` 时始终继续显示“正在读取并比较两端收藏”，不读取合并阶段字段。

## 错误与兼容

- 阶段更新持久化失败时沿用现有同步错误处理，不继续以不准确状态执行。
- 前后端短暂版本不一致时，未知或缺失阶段字段回退到“正在同步收藏”，不会阻塞同步。
- 进入错误状态时仍展示现有错误信息和“重试同步”按钮，不保留过时阶段文案。

## 测试

后端测试应通过可控的假远端依次观察三个阶段，确认阶段切换发生在对应操作之前、进度在阶段切换时重置，并确认成功、失败、关闭及账号切换会清空阶段。API 合约测试应覆盖三个枚举值及空值。

前端测试应覆盖三个阶段到中文文案的映射、未知值的安全回退，以及 `checking` 状态仍显示原有“正在读取并比较两端收藏”。最后运行后端测试、前端测试、Lint、格式检查和生产构建。

## 验收标准

- 点击“合并两端”后，进度条每次重新计数时，上方文案分别准确显示拉取、上传、检查三个阶段。
- 点击“重新检查”时，截图中的“正在读取并比较两端收藏”保持不变。
- 页面中不出现收藏条目列表或额外日志。
- 合并、失败重试及日常收藏同步行为与修改前一致。
